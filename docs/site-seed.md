# سید سایت

فایل اصلی داده‌ها: `apps/catalog/industry_content.json`.
فایل اجرایی: `apps/common/management/commands/seed_site.py`.
عکس‌های همراه: `static/img/references/`.

از ریشهٔ پروژه اجرا کنید:

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_site
```

این دستور بدون اتصال به شبکه، ۱۲ نوع تابلو، ۱۸ نمونهٔ واقعی، ۷ دستهٔ کسب‌وکار و شهرهای تهران، کرج و مشهد را وارد می‌کند. عکس‌ها به فضای media کپی می‌شوند. معرفی ۷ مجموعه از JSON خوانده می‌شود؛ حساب عضو برای آن‌ها ساخته نمی‌شود. منبع عکس‌ها و داده‌ها در داخل پروژه نگهداری می‌شود و در صفحات عمومی نمایش داده نمی‌شود.

دستور با نامک‌ها داده‌های همین مجموعه را به‌روزرسانی می‌کند؛ اجرای چندباره رکورد تکراری ایجاد نمی‌کند. اگر نامک نمونهٔ واقعی با نمونه‌کار یک عضو تداخل داشته باشد، عملیات دیتابیس بازگردانده می‌شود. هیچ حساب، سفارش، نظر، قیمت یا امتیاز ساختگی ایجاد نمی‌شود.

این سید مقاله یا ایدهٔ هوش مصنوعی جدید نمی‌سازد. عکس و توضیح تصویرِ سه مقالهٔ راهنمای اولیه، در صورت وجود، با تصاویر واقعی همگام می‌شود. طراحی گالری، فوتر و تصویر لندینگ در فایل‌های قالب و static پروژه قرار دارند و نیازی به سید دیتابیس ندارند.

برای بایگانی داده‌های دقیقِ سید آزمایشی قبلی، فقط در پیش‌نمایش با `DEBUG=True`:

```bash
.venv/bin/python manage.py seed_site --archive-demo
```

این گزینه اختیاری است؛ اجرای عادی سید داده‌های قبلی کاربران را حذف نمی‌کند.

همهٔ ۱۸ نمونهٔ تصویری این سید با وضعیت منتشرشده وارد می‌شوند. اجرای دوباره، نمونه‌های همین سید را مجدداً منتشر می‌کند؛ وضعیت پیش‌نویس‌های کاربران را تغییر نمی‌دهد. فهرست نمونه‌کارها صفحه‌بندی دارد و با دکمهٔ «صفحهٔ بعد» می‌توان بقیهٔ موارد را دید.

تمام عکس‌های تابلو در `static/img/references/` باید در فهرست پروژه‌های JSON رکورد داشته باشند؛ تست تطبیق فایل‌ها این موضوع را کنترل می‌کند. `diba-office.webp` عکس فضای اداری مجموعه است و فقط برای معرفی آن استفاده می‌شود. عکس‌های صبح، روز، غروب و شب، حالت‌های نوری همان تصویرند و نمونه‌کار جداگانه نیستند. نشانی فایل اصلی برای ۷ نمونهٔ تکمیلی در دادهٔ همراه موجود نبود؛ این فیلد خالی است و وب‌سایت منبع آن‌ها نگهداری شده است.
