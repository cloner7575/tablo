# اتصال اختصاصی تابلوسازان به ChatGPT

## قرارداد و استقرار

- وابستگی SDK: `mcp==1.30.0`؛ نصب با `pip install -r requirements.txt`.
- اجرای migrationهای integrations و portfolio با `python manage.py migrate`.
- `PUBLIC_SITE_URL` در تنظیمات از `DJANGO_SITE_URL` خوانده می‌شود؛ آن را روی origin عمومی HTTPS، بدون مسیر و اسلش پایانی تنظیم کنید.
- اجرا با `daphne -b 0.0.0.0 -p 8000 core.asgi:application`؛ WSGI ابزارهای MCP را اجرا نمی‌کند. Django و Channels همچنان از همان ASGI application استفاده می‌کنند.
- endpoint ثابت: `/mcp/`. پراکسی باید Authorization و Host اصلی را حفظ کند، HTTP POST و پاسخ JSON را عبور دهد و Origin جعلی تزریق نکند. نشست‌ها stateless هستند و به sticky session نیاز ندارند.
- discovery در `/.well-known/oauth-authorization-server` و `/.well-known/oauth-protected-resource` ارائه می‌شود. OAuth از ثبت پویای کلاینت عمومی (DCR)، authorization code، PKCE S256 و resource binding استفاده می‌کند؛ کلاینت CIMD یا PAT در این نسخه ارائه نمی‌شود.
- مجوزها: `vendor:read` برای مشاهده، `vendor:write` برای ذخیره و تغییر، `offline_access` برای دریافت refresh token. مجوزها در سرور اعمال می‌شوند. همه ابزارها به Bearer معتبر نیاز دارند.
- رضایت ۱۵ دقیقه، کد ۵ دقیقه، access token یک ساعت و refresh token سی روز اعتبار دارند. تمدید، توکن قبلی را باطل می‌کند؛ توکن‌های خام ذخیره یا نمایش داده نمی‌شوند.
- دیتابیس PostgreSQL برای قفل‌های مصرف کد، تمدید توکن، قطع اتصال و اجرای عملیات لازم است. Redis مشترک را برای rate limit چند پردازه فعال کنید؛ locmem محدودیت هر پردازه دارد.
- `PRIVATE_MEDIA_ROOT` به‌صورت پیش‌فرض `private-media/` خارج از MEDIA_ROOT است. این پوشه را به یک volume پایدار و خصوصی متصل و در پشتیبان‌گیری لحاظ کنید. هرگز آن را در nginx یا CDN به‌صورت عمومی mount نکنید. Dockerfile و entrypoint مالکیت پوشه را برای appuser آماده می‌کنند.
- URLهای فایل OAuth یا دانلود موقت را در access log، error tracking یا tracing ثبت نکنید. روی مسیرهای authorize و token و مبدأ دریافت فایل، ثبت query string/body و هدر Authorization را غیرفعال کنید. Audit داخلی فقط نوع عملیات و شناسه رکورد را نگه می‌دارد.

## اتصال تابلوساز

در پنل، «اتصال به ChatGPT» آدرس، راهنمای فارسی، اتصال‌های فعال، قطع دسترسی، زمان آخرین استفاده، طرح‌های خصوصی و فعالیت‌های اخیر را نشان می‌دهد.

امکان افزودن MCP سفارشی به قابلیت‌های حساب و سیاست فضای کاری ChatGPT وابسته است؛ نمایش این صفحه به‌معنای فعال‌بودن این قابلیت در همه حساب‌ها نیست. رابط و شرایط دسترسی ممکن است تغییر کنند. اتصال اختصاصی با انتشار عمومی در فهرست ChatGPT متفاوت است.

منابع رسمی بررسی‌شده:

- https://developers.openai.com/plugins/build/auth
- https://developers.openai.com/plugins/reference#define-file-inputs
- https://developers.openai.com/plugins/build/chatgpt-ui

## ابزارها

- `panel_summary`, `get_profile`, `list_records`, `read_messages`, `design_brief`: داده‌های مجاز خود تابلوساز. فهرست notifications در این نسخه پیام‌های خوانده‌نشده است؛ لاگ اعلان قدیمی که کلید مالک ندارد بر اساس شماره تلفن افشا نمی‌شود.
- `save_design`: ورودی فایل ChatGPT با `download_url` و `file_id` الزامی؛ `mime_type` و `file_name` اختیاری. ثبت `openai/fileParams` روی file. فقط تصویر واقعی PNG/JPEG/WebP تا سقف فعلی سایت و ۲۵ میلیون پیکسل؛ تصویر بازخوانی و به PNG بدون metadata تبدیل می‌شود.
- دانلود فقط HTTPS روی ۴۴۳، با بررسی همه IPهای DNS و اتصال به یک IP عمومی ثابت و TLS معتبر؛ redirect مجاز نیست. سقف بایت و زمان دریافت اعمال می‌شود. نشانی `sandbox:` ورودی دانلود نیست.
- `view_design`: تصویر خصوصی حساب فعلی به‌صورت MCP ImageContent.
- `show_design_saver`: کارت انتخاب فایل/پیوست در همان ChatGPT، عنوان و شماره اختیاری پروژه، ذخیره خصوصی و پیش‌نمایش نتیجه. این کارت از extensionهای فایل ChatGPT با feature detection استفاده می‌کند؛ در میزبان فاقد آن‌ها پیام راهنما دارد.
- `prepare_operation`: پیش‌نویس تغییرناپذیر با اعتبار سی دقیقه برای quote، message، design، stage، profile، portfolio، publish.
- `confirm_operation`: اجرای همان پیش‌نویس، پس از نمایش و تأیید صریح انسان در گفتگو. annotationهای ابزار و توضیحات، کلاینت را به گرفتن تأیید هدایت می‌کنند؛ سرور قادر به تشخیص مستقل یک جمله انسانی در تاریخچه ChatGPT نیست. برای تأیید مستقل از کلاینت باید در آینده دکمه تأیید در پنل اضافه شود.
- اجرای دوباره همان operation_id نتیجه ذخیره‌شده را برمی‌گرداند. نسخه رکوردهای هدف هنگام تأیید بررسی و قفل می‌شود؛ تغییر نسخه، نیاز به پیش‌نویس تازه دارد. عملیات به اتصال ایجادکننده محدود است.
- ساخت/ویرایش نمونه‌کار ابتدا غیرعمومی است؛ انتشار مرحله جدا دارد. نمونه‌کار عمومی پیش از ویرایش باید از انتشار خارج شود. تصاویر AI دارای فیلد ماندگار `is_ai_concept` و برچسب عمومی هستند.
- تأیید طرح و تکمیل نهایی سفارش از جانب مشتری ارائه نمی‌شود؛ تغییر مرحله تابلوساز فقط از قواعد سرویس موجود عبور می‌کند. حذف حساب، پرداخت و دسترسی مدیریتی ارائه نمی‌شوند.

## آزمون پذیرش واقعی

آزمون‌های خودکار از سرور واقعی SDK روی ASGI و دیتابیس تست PostgreSQL استفاده می‌کنند؛ فایل شبکه در آزمون ابزار mock می‌شود و محافظت DNS/redirect جدا آزمایش می‌شود. این‌ها جای آزمون ChatGPT واقعی را نمی‌گیرند.

بعد از استقرار HTTPS:

1. با دو تابلوساز تأییدشده اتصال جدا بسازید؛ پروفایل، نمونه‌کار، تصویر، گفتگو و پروژه خصوصی هرکدام برای دیگری غیرقابل دسترس باشد.
2. در ChatGPT یک تصویر واقعی بسازید و بخواهید مستقیم با save_design ذخیره شود؛ دریافت فایل واقعی و مشاهده در پنل را بررسی کنید.
3. مسیر جایگزین show_design_saver را با انتخاب فایل و پیوست آزمایش کنید. اگر فایل تصویر تولیدشده در اختیار ابزار قرار نگرفت، انتخاب/پیوست لازم است؛ تولید تصویر یک ابزار سرور نیست.
4. پیشنهاد یا پیام را آماده کنید، پیش‌نمایش را ببینید، تأیید کنید و همان شناسه را دوباره اجرا کنید؛ فقط یک ارسال رخ دهد.
5. اتصال را از پنل قطع کنید؛ access و refresh قبلی و تصویر خصوصی با آن دسترسی قابل استفاده نباشد.

انتشار عمومی plugin، دسترسی به حساب ChatGPT واقعی، تنظیم دامنه و استقرار بیرونی بخشی از آزمون محلی نیست و به‌طور خودکار انجام نمی‌شود.
